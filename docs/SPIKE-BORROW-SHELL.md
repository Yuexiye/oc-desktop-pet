# Spike: 借壳路线可行性调研

> 评估 VTube Studio (VTS) 和 Wallpaper Engine 作为身体后端
> 日期：2026-09-05
> 作者：奥菲莉娅
> 状态：调研完成

---

## 一、背景

现状：oc-pet 使用自研的 Live2D 渲染器（`avatar/live2d_renderer.py`，2561 行），需要自己处理 GL 初始化、模型加载、表情/动作/视线/口型同步。

目标：评估"借壳"——用现成的 VTube Studio 或 Wallpaper Engine 作为身体后端，oc-pet 只负责大脑 + 感知 + 控制。

---

## 二、VTube Studio 方案

### 2.1 VTS 是什么

VTube Studio (VTS) 是一个 Live2D 模型展示软件，支持：
- Live2D 模型加载和渲染
- 面部追踪（摄像头/屏幕）
- 动作/表情控制
- 外部应用通过 WebSocket API 控制

### 2.2 集成方案

```
oc-pet (大脑 + 感知)
    ↓ WebSocket API
VTube Studio (身体)
    ↓ 渲染
Live2D 模型
```

oc-pet 通过 VTS 的 WebSocket API 控制：
- 设置表情（`SetExpression`）
- 播放动作（`PlayMotion`）
- 控制视线（`SetEyePosition`）
- 控制口型（`SetMouthShape`）

### 2.3 可行性

| 维度 | 评估 | 说明 |
|---|---|---|
| 技术可行性 | ✅ 高 | VTS 有完整的 WebSocket API 文档 |
| 工作量 | 🟡 中 | 需要写 WebSocket 客户端 + API 适配层 |
| 用户门槛 | 🟡 中 | 用户需要额外安装 VTS（免费但有 2K 水印） |
| 维护成本 | ✅ 低 | VTS 团队维护渲染，oc-pet 只维护 API 适配 |
| 模型兼容性 | ✅ 高 | VTS 支持所有 Live2D 3/4 模型 |

### 2.4 工作量估算

| 任务 | 工时 |
|---|---|
| WebSocket 客户端封装 | 2-3 天 |
| API 适配层（表情/动作/视线/口型） | 3-5 天 |
| 配置集成（VTS 连接设置） | 1-2 天 |
| 测试 + 文档 | 2-3 天 |
| **总计** | **8-13 天** |

### 2.5 风险

- VTS 免费版有 2K 水印，用户需要付费（¥99）才能去水印
- VTS API 可能变化，需要跟踪更新
- 用户需要额外安装 VTS，增加使用门槛

## 三、Wallpaper Engine 方案

### 3.1 Wallpaper Engine 是什么

Wallpaper Engine 是一个动态壁纸软件，支持：
- Live2D 模型作为壁纸
- 鼠标/键盘/音频交互
- 跨平台（Windows/Linux）

### 3.2 集成方案

```
oc-pet (大脑 + 感知)
    ↓ 文件/命令
Wallpaper Engine (身体)
    ↓ 渲染
Live2D 模型（壁纸）
```

oc-pet 通过文件触发或命令控制：
- 表情/动作通过文件信号触发
- 视线/口型通过文件读取实时数据

### 3.3 可行性

| 维度 | 评估 | 说明 |
|---|---|---|
| 技术可行性 | 🟡 中 | 没有官方 API，需要文件/命令触发 |
| 工作量 | 🔴 高 | 需要自己实现触发机制，不稳定 |
| 用户门槛 | 🟡 中 | 用户需要额外安装 WE（Steam 付费） |
| 维护成本 | 🟡 中 | 需要维护触发机制，容易失效 |
| 模型兼容性 | ✅ 高 | WE 支持所有 Live2D 模型 |

### 3.4 工作量估算

| 任务 | 工时 |
|---|---|
| 触发机制设计（文件/命令） | 3-5 天 |
| 信号格式定义 | 1-2 天 |
| 表情/动作触发实现 | 3-5 天 |
| 视线/口型实时同步 | 5-7 天 |
| 测试 + 文档 | 3-5 天 |
| **总计** | **15-24 天** |

### 3.5 风险

- 没有官方 API，触发机制不稳定
- 文件触发有延迟，不适合实时同步（视线/口型）
- WE 是 Steam 付费软件（¥38）
- Linux 支持但模型兼容性可能有问题

## 五、建议

### 5.1 短期（0-1 个月）

**维持现状**：oc-pet 自研渲染器继续运行，不做借壳。

理由：
- 已有 2561 行渲染器，维护成本虽高但稳定
- VTS 方案需要用户付费，增加门槛
- WE 方案不稳定，不推荐

### 5.2 中期（1-3 个月）

**可选 VTS 适配**：如果用户反馈强烈，可以做一个 VTS 适配层（8-13 天）。

条件：
- 用户愿意付费去 VTS 水印
- 用户愿意额外安装 VTS
- 有明确的用户需求

### 5.3 长期（3-6 个月）

**保持自研**：继续优化自研渲染器，不做借壳。

理由：
- 自研是护城河，借壳会降低差异化
- VTS/WE 都有付费门槛，增加用户流失
- 维护成本虽高，但可控

---

## 六、结论

**借壳路线不推荐**。

- VTS 方案技术可行，但用户门槛高（付费）
- WE 方案技术不稳定，不推荐
- 自研渲染器虽维护成本高，但是护城河

**建议**：维持现状，继续优化自研渲染器。如果未来有强烈的用户需求，可以考虑做 VTS 适配层作为可选项。
