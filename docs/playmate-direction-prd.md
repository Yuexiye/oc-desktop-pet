# oc-pet 陪玩游戏方向 · 需求文档（PRD）

> 状态：**规划中（未来方向，非立即开发）**
> 作者：产品经理 许清楚（Alice）
> 日期：2026-08-16
> 版本：v0.1（评审稿）
> 关联文档：`docs/playmate-gap-analysis.md`（市场差距分析）
> 原始需求：让桌宠"陪玩游戏"——识别游戏场景、观战吐槽、加油打气、游戏副官。参考竞品：猫娘计划 Project N.E.K.O. 的泰拉瑞亚猫娘陪玩（BV1Qcby6HEQ7）、红警猫娘副官（BV1big36CEdp）。

## 1. 产品定义

### 1.1 产品目标（3 个正交目标）

| 目标 | 一句话 | 衡量标准（示意） |
|------|--------|----------------|
| **看得懂** | 从"知道用户在玩游戏"升级为"看得懂游戏内发生了什么"（对局/战斗/胜负/剧情/资源） | 游戏状态识别准确率 ≥ 80%；支持 ≥ 3 款首发游戏 |
| **说得对** | 吐槽/加油/播报符合游戏语境与用户心情，不尬聊、不打扰 | 用户可配置打扰频率；对局中默认低打扰 |
| **陪得住** | 长时游戏过程中稳定陪伴——不崩溃、不抢屏、不打断操作、记得上次战局 | 游戏会话期间桌宠零崩溃；下次启动能接上上次话题 |

### 1.2 目标场景（5 个）

| # | 场景 | 桌宠行为示例 | 优先级 |
|---|------|------------|:---:|
| 1 | **二次元大世界**（原神 / 星穹铁道等） | 探索时安静陪伴；战斗时喊加油；抽卡出货"太欧了"、歪了"保底人保底魂" | P0 |
| 2 | **MOBA 对战**（英雄联盟 / DOTA2 等） | 观战吐槽（击杀/团灭/推塔）；复活等待聊天；胜利"这把有你"、失败"没关系再来" | P0 |
| 3 | **Steam 单机**（泰拉瑞亚 / 红警等） | 副官式播报（资源/警报）；boss 战加油；剧情推进有反应 | P0 |
| 4 | **休闲/派对游戏**（雀魂 / 糖豆人 / 双人成行等） | 轻量陪伴，偶尔插话不打扰 | P1 |
| 5 | **看游戏直播/攻略视频**（延伸场景） | 复用现有 `video_watching` 场景，看别人玩也能聊 | P1 |

### 1.3 用户故事（"我"视角）

1. 作为玩家，我希望桌宠在我打 boss 快赢时喊"就差一点了，加油！"，这样我感觉有人陪着打游戏。
2. 作为玩家，我希望桌宠在我对局中途**不频繁说话**，这样不干扰我操作、不让我分心送人头。
3. 作为玩家，我希望桌宠在我胜利时说"太强了！"、失败时说"没关系，再来一局"，这样我的情绪有回应。
4. 作为玩家，我希望桌宠记住我上次玩的游戏和进度，下次启动时接着聊"你上次那个 boss 过了吗"。
5. 作为玩家，我希望桌宠能按游戏切换吐槽风格（在红警里不说原神的话），这样不违和、不跳戏。

## 2. 需求池（P0 / P1 / P2）

> P0 = 陪玩 MVP 必须；P1 = 体验增强应该；P2 = 进阶/暂缓可以。

### 2.1 P0（MVP 刚需）

| ID | 需求 | 需求描述 | 验收要点（示意） |
|----|------|---------|----------------|
| P0-1 | **游戏窗口识别** | 通过进程名/窗口标题匹配游戏白名单，感知游戏启动/退出 | 支持 ≥ 3 款首发游戏；启动/退出事件延迟 ≤ 5s；可配置白名单 |
| P0-2 | **游戏状态感知（基础）** | 识别"对局中 / 等待 / 胜利 / 失败"四态 | 四态识别准确率 ≥ 80%；状态变化延迟 ≤ 15s |
| P0-3 | **场景化吐槽/加油文案池** | 游戏类型 × 状态 × 情绪 → 文案；随状态触发 | 首发 3 款游戏 × 每款 ≥ 30 条；文案不重复、不尬 |
| P0-4 | **语音播报** | 状态变化触发 TTS 播报（复用现有 TTS） | 播报可静音；不阻塞对话队列；支持"安静陪伴"模式 |
| P0-5 | **主动搭话节奏控制** | 对局中延长冷却、关键时刻触发；可配置打扰频率 | 对局中默认 10min+ 冷却；胜利/失败等关键时刻立即触发 |

### 2.2 P1（体验增强）

| ID | 需求 | 需求描述 |
|----|------|---------|
| P1-1 | **多游戏配置** | 游戏库管理：添加游戏、自定义文案与状态规则 |
| P1-2 | **游戏偏好记忆** | 扩展 CompanionMemory：常玩游戏 / 上次进度 / 胜负记录 |
| P1-3 | **情绪→表情映射增强** | 胜利/失败/紧张等游戏态映射到不同动画表情 |
| P1-4 | **VoiceClone 音色克隆** | 少样本音色克隆，提升拟真感 |
| P1-5 | **观战模式** | 看直播/攻略视频也触发（复用 `video_watching` 场景） |
| P1-6 | **LLM 实时文案生成** | 内置模板之外，允许 LLM 实时生成游戏语境吐槽（可配置开关，控成本） |

### 2.3 P2（进阶/暂缓）

| ID | 需求 | 需求描述 |
|----|------|---------|
| P2-1 | **A2A 副官执行** | 查攻略、报战绩、执行简单指令（调用通用 Agent 当"手脚"） |
| P2-2 | **VRM 模型支持** | 3D 形象渲染（`avatar/vrm_renderer.py` 目前为占位） |
| P2-3 | **物理反馈** | 发丝飘动 / 衣物垂坠等物理效果 |
| P2-4 | **社区共创文案包** | 用户投稿游戏文案包，平台化分发 |
| P2-5 | **Steam 发行** | 渠道与社区生态建设 |

## 3. 与现有能力的复用关系

| 新需求 | 复用 oc-pet 现有模块 | 需新增 |
|--------|---------------------|--------|
| P0-1 游戏窗口识别 | `motion/foreground_watcher.py`（进程名/标题）、`core/perception/screen.py`（on_foreground_change 事件） | 游戏白名单配置、启动/退出事件判定 |
| P0-2 游戏状态感知 | `core/perception/screen.py`（视觉模型管道、变化检测、失败退避） | 游戏状态机（对局/等待/胜负）、快节奏采样策略 |
| P0-3 文案池 | `core/perception/scenarios.py`（场景文案池机制）、`screen.py _PROACTIVE_TEMPLATES` | 游戏类型×状态×情绪 的文案库结构 |
| P0-4 语音播报 | `tts_provider/`（Edge TTS/CosyVoice/Mimo 抽象）、`conversation_engine.py` 代际打断 | 游戏播报优先级队列、静音开关 |
| P0-5 节奏控制 | `screen.py _check_screen_proactive`（冷却+概率） | 对局内静默策略、关键时刻触发规则 |
| P1-2 游戏记忆 | `core/companion_memory.py`（上次话题/连续天数） | 游戏维度字段（常玩/进度/胜负） |
| P1-3 表情映射 | `core/emotion_transitions.py`、`scripts/procedural_emotion_frames.py` | 游戏态→情绪/表情映射表 |

## 4. 待确认问题（Open Questions）

> 这些是架构师/开发评审前需要确认的技术可行性问题，本 PRD 不替技术下结论。

| # | 问题 | 影响 | 建议讨论方 |
|---|------|------|-----------|
| 1 | **游戏画面深度识别的技术路线**：纯视觉大模型周期截图 vs 窗口标题+OCR vs 混合方案？各自成本/延迟/准确率如何？ | 决定 P0-2 的实现方式与 API 成本 | 架构师 + 开发 |
| 2 | **采样节奏**：现有屏幕感知基准 120s（随机±30%）对游戏太慢；游戏内是否需要 5-10s 采样？API 成本是否可承受？ | 直接决定 P0-2 成本模型 | 开发 |
| 3 | **窗口标题信息够用吗**：LOL/Steam 多数游戏窗口标题稳定但无状态；全屏无边框游戏标题可读性？能否作为状态感知的低成本兜底？ | 影响 P0-2 准确率与成本 | 开发 |
| 4 | **TTS 播报打断策略**：游戏播报与用户语音输入/对话如何仲裁？是否引入"游戏播报优先级队列"？与现有代际打断如何协同？ | 决定 P0-4 体验边界 | 开发 |
| 5 | **隐私**：游戏内聊天/账号截图如何处理？是否默认对游戏画面模糊？黑名单机制（密码/支付）是否扩展到游戏？ | 合规与信任 | PM + 开发 |
| 6 | **性能**：全屏独占游戏下 `ImageGrab.grab` 的截图成本？对帧率/GPU 的影响？是否需要降采样策略？ | 决定"陪得住"目标是否成立 | 开发 |
| 7 | **文案生成方式**：内置模板 vs LLM 实时生成？成本/一致性/风格如何权衡？是否学 N.E.K.O. 走社区共创？ | 决定 P0-3 与 P2-4 的内容策略 | PM + 开发 |
| 8 | **首发游戏优先级**：二次元大世界 / MOBA / Steam 单机 先做哪个？取决于目标用户画像与竞品错位 | 决定 P0 白名单 | PM 定夺 |

## 5. 范围边界（明确不做 / 延后）

### 5.1 明确不做（合规红线，任何阶段都不做）

- ❌ **不做游戏外挂/辅助功能**：不读取游戏内存、不注入进程、不改写游戏文件、不提供自动瞄准/加速等。
- ❌ **不做自动操作**：不替玩家操作角色、不代打、不自动点击。

### 5.2 延后（不在本轮陪玩方向内）

- ⏸ **Steam 发行**：渠道/商业/法务/社区运营需单独立项，非功能问题。
- ⏸ **VRM 模型 + 物理反馈**：观感升级项，Live2D 初音可先承担陪玩形象。
- ⏸ **A2A 副官执行**：MVP 陪玩 = 吐槽 + 加油 + 播报，不需要"手脚"；副官化是 P2 终局。
- ⏸ **多语言**：先中文。
- ⏸ **手机游戏**：先 PC 端游 / Steam，移动端（原神手机版等）依赖手机感知链路（现有 `phone_activity.py` 走 MacroDroid），另行评估。

### 5.3 边界说明

- ⚠️ **游戏适配不是"通用全游戏"**：先做白名单 3-5 款热门游戏，验证"状态感知 + 文案池"跑通后，再通过 P1-1 多游戏配置开放给用户自行添加。
- ⚠️ **不承诺 100% 识别**：视觉识别存在误判，P0-2 目标准确率 ≥ 80%，其余以"安静陪伴模式"兜底（识别不了就不打扰）。

## 6. 里程碑建议（供排期参考，非本次开发承诺）

| 阶段 | 内容 | 退出标准（示意） |
|------|------|----------------|
| M0 预研 | 确认待确认问题 1-8；跑通 1 款游戏的窗口识别 + 状态感知 Demo | Demo 能识别"对局中/胜利/失败" |
| M1 MVP | P0-1 ~ P0-5，支持 3 款首发游戏 | 3 款游戏 × 30 条文案；状态识别 ≥ 80%；可静音 |
| M2 增强 | P1-1 ~ P1-6 | 多游戏配置开放；游戏记忆生效；VoiceClone 可用 |
| M3 进阶 | P2-1 ~ P2-5（选择性） | 副官执行/VRM/社区共创 按需启动 |
